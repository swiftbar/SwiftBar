## Build 625 image-visibility follow-up

Build-625 product commit: [`a1a5150`](https://github.com/swiftbar/SwiftBar/commit/a1a5150447c2c12453d2ed0fd644117ad76214f9), reviewed in [#602](https://github.com/swiftbar/SwiftBar/pull/602). The build-626 follow-up is recorded below.

The maintainer supplied a native build-624 dropdown screenshot (`menu-visibility/reporter-menu.png`). It showed the graph and final marker but omitted the multiline image and default timer. An isolated AppKit menu probe reproduced omission of native `NSMenuItem.image` with both plain and attributed titles on macOS 27. The previous fallback was therefore insufficient.

All macOS 26+ menu images now use inline attachments. Plain unconfigured symbols receive the menu font's point size and medium scale; explicit dimensions/configurations and status-bar behavior remain intact. Multiline attachments center the image beside the complete text block, reserve measured ascent/descent for tall images, and preserve compact text baselines, native searchable title text, colors, accessibility labels, and actions. Trailing empty paragraphs are included in measurement. Whole-title image rendering and unmeasured paragraph padding were rejected during independent review.

Clipped pixel tests cover 13/37/100-point images against four labels, including leading and trailing newlines. They verify the full intrinsic image survives the measured title bounds, native text remains readable, and incremental replacement retains the title. Independent ordinary/trailing-line clipped proofs passed; final review has no accepted actionable findings (`menu-visibility/reviewer-final-image-synthesis.md`, `menu-visibility/reviewer-trailing-ascent-codex.log`).

The added AppKit tests exposed main-actor starvation when application-hosted tests ran concurrently. The shared scheme disables test parallelization, and the menu suite/parameterized drawing cases serialize their native work; build parallelism remains enabled. No assertions or timeouts were weakened, and explicit product concurrency tests still exercise real threads/queues. Failed runs remain retained. Final default-CLI architecture results are recorded in the table above; zero runtime warnings does not mean zero compiler deprecation/concurrency warnings.

The extracted build-625 dropdown opens through native menu automation and exposes the expected rows. Native menu screenshots remain unavailable through CUA, and `screencapture` lacks permission. Source-linked native drawing probes and clipped pixel tests passed, but they do not substitute for signed-artifact visual, hover, and platform confirmation. Existing permissions remain unchanged.
